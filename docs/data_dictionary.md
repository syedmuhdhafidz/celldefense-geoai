# CellDefense GeoAI Data Dictionary

## Dataset Overview

| Item | Definition |
| --- | --- |
| Dataset name | CellDefense Synthetic RF Drive-Test Dataset |
| Primary purpose | Train and evaluate spatial anomaly detection for suspicious base-station behaviour |
| Data source | Team-generated synthetic observations |
| Pilot area | Cyberjaya, Sepang, Selangor |
| Geographic bounds | Latitude 2.8900–2.9700; longitude 101.6200–101.7000 |
| Planned simulation period | Seven synthetic days |
| Temporal resolution | One observation per second during a simulated drive |
| Approximate raw spatial resolution | Approximately 10–20 metres at ordinary driving speed |
| Analysis resolution | 50-metre spatial cells and 5-minute time windows |
| Coordinate system | WGS 84, EPSG:4326 |
| Ground truth | Scenario and anomaly labels generated by the simulator |
| Personal data | None |
| Subscriber identifiers | Prohibited |

## Important Interpretation

The `is_anomaly` field represents synthetic ground truth produced by the simulator.

It does not confirm that an IMSI catcher, rogue base station, malicious transmitter, or cybersecurity incident exists in the real world.

The final model output will be an investigation-priority score, not a declaration that an offence or attack has occurred.

## Observation Fields

| Column | Type | Description | Example |
| --- | --- | --- | --- |
| `observation_id` | String | Unique identifier for one observation | `obs-000001` |
| `timestamp` | ISO 8601 timestamp | Time at which the observation occurred | `2026-08-08T08:00:00+08:00` |

| `operator_id` | String | Fictional operator identifier | `OP_A` |
| `rat` | Category | Radio access technology: `LTE` or `NR` | `LTE` |

| `pci` | Integer | Physical Cell Identifier | `101` |

## Allowed Scenarios

### Benign scenarios

| Scenario | Meaning |
| --- | --- |
| `baseline` | Expected network behaviour |
| `legitimate_new_cell` | A properly introduced new base station |
| `maintenance` | Temporary legitimate network maintenance |
| `gps_error` | Incorrect or noisy sensor location |
| `device_bias` | Signal variation caused by sensor hardware |

### Suspicious simulated scenarios

| Scenario | Meaning |
| --- | --- |
| `cloned_cell` | A cell identifier appears in a geographically inconsistent location |
| `short_lived_cell` | An unusual cell appears briefly and then disappears |
| `handover_oscillation` | Observations exhibit repeated abnormal handover behaviour |

## Explicitly Prohibited Fields

The validation layer rejects the following fields:

- IMSI
- IMEI
- MSISDN
- Phone number
- Subscriber identifier
- Message content

## Known Limitations

1. Synthetic propagation will not reproduce every building, terrain, weather, antenna, device, and operator effect.
2. Synthetic anomaly classes reflect scenarios designed by the project team.
3. Model performance on synthetic data does not establish real-world detection performance.
4. Driving routes create road-network sampling bias.
5. Signal readings can vary between device models.
6. OpenCellID, if later used, is crowdsourced and must not be treated as an authoritative operator registry.
7. A suspicious observation may be caused by legitimate maintenance, configuration changes, faulty equipment, GPS error, or measurement noise.
